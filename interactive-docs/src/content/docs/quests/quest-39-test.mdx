## 📖 Concept: Test Coverage Analysis

Test coverage คือ measure ว่า codebase ของคุณถูก test ครอบคลุมแค่ไหน — แต่ **coverage percentage ไม่ใช่ทุกอย่าง**

โค้ดที่มี coverage 100% อาจยังมี bugs ได้ ถ้า tests ไม่ได้ test ถูก scenario — และโค้ดที่มี coverage 60% อาจปลอดภัยกว่า ถ้า critical paths ถูก test ดี

AI ช่วยวิเคราะห์ test suite ของคุณ — ไม่ใช่แค่ดู % coverage แต่ดู **quality** ของ tests ด้วย

## ⚙️ How It Works

### กระบวนการ Test Analysis

```
1. SCAN — สแกน test files และ source files
         ↓
2. MAP — map ว่า test ไหน cover function ไหน
         ↓
3. GAP — หา functions ที่ไม่มี tests
         ↓
4. PRIORITY — จัดลำดับตาม risk
         ↓
5. RECOMMEND — แนะนำว่าควรเขียน test อะไรต่อ
```

### วิธีวิเคราะห์ Coverage

```javascript
function analyzeCoverage(sourceCode, testCode) {
  // หา functions ทั้งหมดใน source
  const sourceFunctions = extractFunctions(sourceCode);
  
  // หา functions ที่ถูกเรียกใน tests
  const testedFunctions = extractTestedFunctions(testCode);
  
  // หา gaps
  const gaps = sourceFunctions.filter(fn => 
    !testedFunctions.includes(fn.name)
  );
  
  return {
    total: sourceFunctions.length,
    covered: sourceFunctions.length - gaps.length,
    coverage: ((sourceFunctions.length - gaps.length) / sourceFunctions.length * 100).toFixed(1),
    gaps: gaps.map(fn => ({
      name: fn.name,
      risk: fn.complexity > 10 ? 'high' : fn.complexity > 5 ? 'medium' : 'low'
    }))
  };
}
```

### Priority Matrix

| Risk Level | Criteria | Action |
| --- | --- | --- |
| **High** | Complex logic + no tests | เขียน test ก่อน |
| **Medium** | Simple logic + no tests | เขียน test เร็วๆ |
| **Low** | Edge functions + no tests | เขียนเมื่อมีเวลา |
| **Covered** | มี tests แล้ว | ตรวจสอบ quality |

## 💡 Example: วิเคราะห์ Test Suite

```javascript
// Source functions
const functions = [
  { name: 'validateEmail', complexity: 3, critical: true },
  { name: 'calculateTotal', complexity: 8, critical: true },
  { name: 'formatDate', complexity: 2, critical: false },
  { name: 'processPayment', complexity: 12, critical: true },
  { name: 'logError', complexity: 1, critical: false }
];

// Tests ที่มีอยู่
const tests = ['validateEmail', 'formatDate'];

// Analysis result
const analysis = {
  total: 5,
  covered: 2,
  coverage: '40.0%',
  gaps: [
    { name: 'calculateTotal', risk: 'high', reason: 'complexity 8 + no tests' },
    { name: 'processPayment', risk: 'high', reason: 'complexity 12 + critical' },
    { name: 'logError', risk: 'low', reason: 'simple + not critical' }
  ],
  recommendation: 'Focus on processPayment first — highest complexity and critical'
};
```

## ⚠️ Common Mistakes

**Mistake 1: พอใจกับ coverage % สูงๆ**
> "Coverage 90% แล้ว ไม่ต้องเขียน test เพิ่ม"
> → 10% ที่เหลืออาจเป็น critical functions — ดูว่า functions ไหนไม่ได้ test

**Mistake 2: นับ trivial tests**
> "มี 100 tests แล้ว"
> → Quality > quantity — test ที่ไม่ assert อะไรเลยไม่มีค่า

**Mistake 3: ไม่ prioritize ตาม risk**
> "เขียน test ทุก functions เท่าๆ กัน"
> → Critical + complex functions ควร test ก่อน — risk-based testing

**Mistake 4: ไม่ review test quality**
> "tests ผ่านทุกตัว ดีแล้ว"
> → ตรวจสอบว่า tests จริงๆ ตรวจสอบ behavior หรือแค่ assert true
