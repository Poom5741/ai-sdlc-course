## 📖 Concept: GitHub Issues & Templates

GitHub Issues เป็นเครื่องมือจัดการงานพื้นฐาน — ทุก bug, feature request, และ task ควรอยู่ใน issue เพื่อให้ทีม track ได้ แต่ถ้าทุกคนเขียน issue ไม่เหมือนกัน มันจะกลายเป็นข้อมูลที่ใช้ไม่ได้

Issue templates แก้ปัญหานี้โดยให้โครงสร้างมาตรฐาน: Description, Reproduction Steps, Expected Behavior, Actual Behavior

Think of issue templates like a dojo intake form — every new student fills out the same form so the instructor knows their level, goals, and any injuries. Consistent format = actionable information.

## ⚙️ How It Works

### GitHub Issue JSON Structure

```javascript
{
  title: "Login button not responding on mobile",
  body: "## Description\n\nThe login button doesn't respond...\n\n## Reproduction Steps\n\n1. Open mobile browser...",
  labels: ["bug", "P0"],
  assignees: [],
  state: "open"
}
```

### Label Mapping

| Issue Type | Label |
| --- | --- |
| bug | `bug` |
| feature | `enhancement` |
| task | `chore` |

| Priority | Label |
| --- | --- |
| high | `P0` |
| medium | `P1` |
| low | `P2` |

## 💡 Example: Creating an Issue

```javascript
const TYPE_LABELS = { bug: 'bug', feature: 'enhancement', task: 'chore' };
const PRIORITY_LABELS = { high: 'P0', medium: 'P1', low: 'P2' };

function createIssue(title, description, type, priority) {
  const labels = [];
  if (TYPE_LABELS[type]) labels.push(TYPE_LABELS[type]);
  if (PRIORITY_LABELS[priority]) labels.push(PRIORITY_LABELS[priority]);

  const body = `## Description

${description}

## Reproduction Steps

1. (Describe the steps to reproduce)
2. (Include environment details)
3. (Include any error messages)

## Expected Behavior

(What should happen instead)

## Actual Behavior

(What actually happens)
`;

  return {
    title,
    body,
    labels,
    assignees: [],
    state: 'open',
  };
}

// Usage:
createIssue(
  "Login fails on mobile",
  "The login button does not respond on iOS Safari",
  "bug",
  "high"
);
```

**Key insight:** AI อาจสร้าง issue ที่ดูดีแต่ไม่มี structured sections — template ที่ดีต้องมีทุก section ที่จำเป็นสำหรับ debugging

## ⚠️ Common Mistakes

**Mistake 1: ไม่ map type/priority เป็น labels**
> AI สร้าง issue โดยไม่ translate type เป็น GitHub label
> → Issue ไม่มี label = จัดการยาก

**Mistake 2: Body ไม่มี structured sections**
> AI เขียน body เป็น paragraph เดียว
> → ไม่มี reproduction steps = developer แก้ไขยาก

**Mistake 3: ใช้ type ที่ไม่ valid**
> AI ใช้ "error" แทน "bug" หรือ "improvement" แทน "feature"
> → ไม่ match label mapping

**Mistake 4: ลืม set state เป็น 'open'**
> AI ไม่ set state field
> → Default อาจไม่ใช่ 'open'
