## 📖 Concept: Code Migration ด้วย AI

Code migration คือการแปลงโค้ดจากภาษาหนึ่งไปอีกภาษาหนึ่ง — เช่น Python → JavaScript, Java → TypeScript

นี่คือหนึ่งใน use case ที่ AI ช่วยได้ดีมาก เพราะ AI สามารถจับ **semantic meaning** ของโค้ดได้ — ไม่ใช่แค่แปล syntax แต่เข้าใจว่าโค้ด **ทำอะไร**

เหมือนนักพากย์หนัง — ไม่ได้แปล word-for-word แต่ถ่ายทอด "ความหมาย" และ "อารมณ์" ไปอีกภาษาหนึ่ง

## ⚙️ How It Works

### ขั้นตอนของ Code Migration

```
1. PARSE — วิเคราะห์ source code
         ↓
2. UNDERSTAND — จับ logic และ data flow
         ↓
3. MAP — หา equivalent ใน target language
         ↓
4. TRANSLATE — แปลงโค้ด
         ↓
5. VERIFY — ทดสอบว่า logic เหมือนเดิม
```

### ความท้าทายที่ AI ต้องจัดการ

| ความท้าทาย | ตัวอย่าง |
| ------------ | ---------- |
| **Data types** | Python `list` → JS `Array` |
| **Error handling** | Python `try/except` → JS `try/catch` |
| **String formatting** | Python f-string → JS template literal |
| **Null handling** | Python `None` → JS `null` / `undefined` |
| **Async patterns** | Python `async/await` → JS `Promise` |

## 💡 Example: Python → JavaScript

**Python ต้นฉบับ:**

```python
def greet_users(users):
    results = []
    for user in users:
        if user.get('active', False):
            name = user['name'].strip().title()
            results.append(f"Hello, {name}!")
    return results
```

**JavaScript ที่ AI แปลง:**

```javascript
function greetUsers(users) {
  const results = [];
  for (const user of users) {
    if (user.active === true) {
      const name = user.name.trim().replace(/\b\w/g, c => c.toUpperCase());
      results.push(`Hello, ${name}!`);
    }
  }
  return results;
}
```

**สิ่งที่ AI จัดการได้ดี:**

- `for...in` → `for...of` (idiomatic loop)
- f-string → template literal
- `.get('active', False)` → `user.active === true`
- `.title()` → manual implementation (JS ไม่มี `.title()`)

**สิ่งที่ AI อาจพลาด:**

- Edge case: `user.name` เป็น `undefined`
- `.title()` behavior ต่างกันเล็กน้อยกับ regex replacement

## ⚠️ Common Mistakes

**Mistake 1: 信任 AI 100% โดยไม่ test**
> "AI แปลงเสร็จแล้ว น่าจะใช้ได้"
> → ทดสอบ logic เทียบกับต้นฉบับเสมอ — โดยเฉพาะ edge cases

**Mistake 2: ไม่รู้ target language idioms**
> "แปลง syntax ตรงๆ ก็พอ"
> → โค้ดที่ syntax ถูกแต่ไม่ idiomatic จะ maintain ยาก — เช่น ใช้ `for` loop ทั้งที่ใช้ `.map()` ได้

**Mistake 3: ไม่จัดการ error handling**
> "logic หลักถูกก็พอ"
> → Error handling ต่างกันมาก giữa languages — ต้อง convert ด้วย

**Mistake 4: ไม่ verify data types**
> "Variable ชื่อเดียวกัน น่าจะ type เดียวกัน"
> → Type systems ต่างกัน — Python duck typing ≠ TypeScript strict types
