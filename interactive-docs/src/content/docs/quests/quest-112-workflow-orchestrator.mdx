## 📖 Concept: Tool Orchestration

ในโลกจริง เราไม่ได้ใช้ AI tool เดียว — เราใช้หลาย tools ร่วมกัน เช่น code generator → linter → formatter → test runner. **Workflow Orchestrator** คือ pattern ที่เชื่อม tools เหล่านี้เข้าเป็น pipeline เดียว

**Core Principle: ORCHESTRATE, DON'T OVERBUILD**

แทนที่จะสร้าง monolithic solution ที่ทำทุกอย่าง ให้ใช้ tools ที่มีอยู่แล้วเชื่อมต่อกัน:

```
Input → Tool A → Tool B → Tool C → Result
          │         │         │
          └─────────┴─────────┘
              บันทึก steps ทุก step
```

**Fail-Fast Pattern** — เมื่อ tool ใด tool หนึ่งล้มเหลว ต้องหยุดทันที ไม่ใช่ continue แล้ว collect error ทีหลัง เพราะ tool ถัดไปอาจ depend บน output ของ tool ที่ล้มเหลว

```
Input → Tool A → Tool B → 💥 ERROR
                           │
                           ▼
                    STOP + Record error
                    (Tool C ไม่ถูก execute)
```

## ⚙️ How It Works

### Orchestration Flow

```javascript
orchestrateWorkflow(tools, input)
```

**Input:**

- `tools` — array of `{ name, process, async? }` — แต่ละ tool มีชื่อและ function
- `input` — ค่าเริ่มต้นที่จะส่งเข้า tool ตัวแรก

**Output:**

```javascript
{
  result: <final output>,
  steps: [
    { tool: 'uppercase', input: 'hello', output: 'HELLO' },
    { tool: 'addPrefix', input: 'HELLO', output: 'RESULT: HELLO' },
    // ...
  ]
}
```

### Step-by-Step Execution

```
1. รับ tools[] และ input
         ↓
2. สำหรับแต่ละ tool ใน tools[]:
   a. บันทึก input ปัจจุบัน
   b. เรียก tool.process(input)
   c. บันทึก output
   d. ใช้ output เป็น input ของ tool ถัดไป
   e. ถ้า error → หยุดทันที (fail-fast)
         ↓
3. Return { result: finalOutput, steps: recordedSteps }
```

### Edge Case: Fail-Fast

```javascript
// ❌ Naive: continue หลัง error
for (const tool of tools) {
  try {
    result = tool.process(result);
  } catch (e) {
    errors.push(e);  // ยัง continue อยู่!
  }
}

// ✅ Correct: stop on error
for (const tool of tools) {
  try {
    result = tool.process(result);
  } catch (e) {
    return { result, steps, error: e.message };  // STOP
  }
}
```

## 💡 Example: Chaining Text Processing Tools

**Define tools:**

```javascript
const tools = [
  { name: 'uppercase', process: (s) => s.toUpperCase() },
  { name: 'addPrefix', process: (s) => `RESULT: ${s}` },
  { name: 'addSuffix', process: (s) => `${s}!` },
];
```

**Execute workflow:**

```javascript
const result = orchestrateWorkflow(tools, 'hello');
// {
//   result: 'RESULT: HELLO!',
//   steps: [
//     { tool: 'uppercase', input: 'hello', output: 'HELLO' },
//     { tool: 'addPrefix', input: 'HELLO', output: 'RESULT: HELLO' },
//     { tool: 'addSuffix', input: 'RESULT: HELLO', output: 'RESULT: HELLO!' }
//   ]
// }
```

**Edge case — error in middle:**

```javascript
const errorTool = { name: 'fail', process: () => { throw new Error('boom'); } };
const result = orchestrateWorkflow([tools[0], errorTool, tools[2]], 'hello');
// result.steps.length === 1 (stopped after error)
// result.error === 'boom'
```

**Edge case — empty tools:**

```javascript
orchestrateWorkflow([], 'hello');
// { result: 'hello', steps: [] }  — input ผ่านมาและกลับไปเลย
```

## ⚠️ Common Mistakes

**Mistake 1: Continue after error instead of fail-fast**
> "Let me record the error and keep going"
> → Tool ถัดไปอาจ depend บน output ที่ไม่มี — fail-fast ป้องกัน cascading errors

**Mistake 2: Not recording step inputs/outputs**
> "Just return the final result"
> → Steps คือ audit trail — debug และ compliance ต้องการข้อมูลว่าแต่ละ tool ทำอะไร

**Mistake 3: Mutating input directly**
> `input = tool.process(input)` — แต่ละ step ต้องบันทึก input เดิมก่อน transform
> → ใช้ variable แยก: `currentInput` vs `output`

**Mistake 4: Not handling empty tools array**
> "Empty tools won't happen"
> → Return `{ result: input, steps: [] }` — ส่ง input กลับไปโดยไม่ transform


</Steps>
