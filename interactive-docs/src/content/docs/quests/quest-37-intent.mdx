## 📖 Concept: Intent → Test Specification

Intent-spec test generation คือการใช้ AI แปลง "ความตั้งใจ" (intent) ของ feature เป็น test cases ที่พร้อม run

แทนที่คุณจะเขียน tests เองทีละ case — คุณบอก AI ว่า "feature นี้ควรทำอะไร" แล้ว AI จะ generate test specs ที่ครอบคลุมทั้ง:

- **Happy path** — กรณีที่ทุกอย่างถูกต้อง
- **Edge cases** — กรณีขอบ
- **Error cases** — กรณีผิดพลาด

เหมือน Ninjutsu master ที่ให้ลูกศิษย์ describe mission → แล้ว master ออก course of action ให้

## ⚙️ How It Works

### ขั้นตอน Intent → Test Spec

```
1. INTENT — บอกว่า feature ควรทำอะไร (natural language)
         ↓
2. ANALYSIS — AI วิเคราะห์ requirements
         ↓
3. SPEC — สร้าง test scenarios
         ↓
4. ASSERTIONS — ระบุ expected behavior
         ↓
5. EXECUTABLE — แปลงเป็น runnable tests
```

### ตัวอย่าง Intent

```javascript
const intent = {
  feature: "user login",
  description: "User can log in with email and password",
  rules: [
    "Email must be valid format",
    "Password must be at least 8 characters",
    "Return user object on success",
    "Throw error on invalid credentials"
  ]
};
```

### Test Spec ที่ AI 生成

```javascript
const testSpecs = [
  // Happy path
  { name: "valid email and password", input: { email: "user@test.com", password: "pass1234" }, expected: "success" },
  
  // Edge cases
  { name: "email without @", input: { email: "usertest.com", password: "pass1234" }, expected: "error" },
  { name: "empty password", input: { email: "user@test.com", password: "" }, expected: "error" },
  { name: "password too short", input: { email: "user@test.com", password: "pass" }, expected: "error" },
  
  // Error cases
  { name: "non-existent user", input: { email: "nobody@test.com", password: "pass1234" }, expected: "error" },
  { name: "wrong password", input: { email: "user@test.com", password: "wrong123" }, expected: "error" }
];
```

## 💡 Example: Intent-to-Tests Function

```javascript
function generateTestSpecs(intent) {
  const specs = [];
  
  // Happy path — กรณีทุกอย่างถูกต้อง
  specs.push({
    name: `${intent.feature} - valid input`,
    type: 'happy',
    input: generateValidInput(intent),
    expected: 'success'
  });
  
  // Edge cases — จาก rules
  for (const rule of intent.rules) {
    if (rule.includes('must') || rule.includes('required')) {
      specs.push({
        name: `${intent.feature} - violates: ${rule}`,
        type: 'edge',
        input: generateInvalidInput(rule),
        expected: 'error'
      });
    }
  }
  
  // Missing input
  specs.push({
    name: `${intent.feature} - empty input`,
    type: 'edge',
    input: {},
    expected: 'error'
  });
  
  return specs;
}
```

## ⚠️ Common Mistakes

**Mistake 1: สร้าง tests จาก code แทนจาก intent**
> "ดูโค้ดแล้วเขียน test ตามนั้น"
> → Tests ควร验证 behavior ไม่ใช่ implementation — เขียนจาก intent แล้วโค้ดต้องผ่าน

**Mistake 2: ไม่ cover error cases**
> "happy path ผ่านก็พอ"
> → Production bugs มักเกิดจาก error paths — ต้อง test ทั้ง success และ failure

**Mistake 3: Test specs กำกวมเกินไป**
> "ควรทำงานถูกต้อง"
> → ระบุ expected output ให้ชัด — ไม่เช่นนั้น test จะไม่มีความหมาย

**Mistake 4: ไม่ generate edge cases จาก rules**
> "rules ยาว เขียน test จาก common sense ดีกว่า"
> → Rules คือ constraints ที่ต้อง test ทุกข้อ — AI ช่วย generate ได้ครบ
