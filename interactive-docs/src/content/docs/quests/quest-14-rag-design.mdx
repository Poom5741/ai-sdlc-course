# Quest 5.1: RAG Design

<Badge text="🟡 Medium" variant="note" /> <Badge text="20 minutes" variant="note" /> <Badge text="Block 5: Architecture" variant="tip" />

## 🎯 Goal

ออกแบบ **Retrieval-Augmented Generation (RAG)** system เหนือ corpus จริง — เรียนรู้ที่จะ **design สำหรับ failure mode**: วางแผน empty retrieval, low-confidence, และ out-of-corpus queries ไว้ล่วงหน้า

---

## 📋 Instructions

ดึง quest ลงเครื่องแล้วทำตามในเครื่องของคุณ:

```bash
npx degit Poom5741/ai-sdlc-course/quests/block-5-architecture/quest-13-rag-design my-quest
cd my-quest
```

1. **อ่าน workshop docs** ใน `interactive-docs/src/content/docs/` — นั่นคือ **corpus** ที่คุณจะ index
2. **ออกแบบ RAG system** ใน `rag-design.md` ในโฟลเดอร์นี้ โดยครอบคลุม:
   - **Chunking strategy**: จะ split docs ยังไง
   - **Embedding strategy**: model ไหน + embed chunk/query ยังไง
   - **Retrieval quality metric**: วัด retrieval quality ยังไง (เช่น recall@5, NDCG, precision)
   - **Failure handling**: เกิดอะไรขึ้นเมื่อ empty retrieval / low confidence / out-of-corpus queries
   - **Corpus**: เอกสารไหนที่ถูก index

## 💡 Hints

- เลือก corpus เล็กๆ จริง (workshop docs) — corpus เล็กทำให้ failure modes ถูก test ได้ถูก
- ตั้งชื่อ metric อย่างชัดเจน (recall@5, precision@10, NDCG) — "มันก็ได้" ไม่ใช่ design
- failure mode ที่ไม่มี fallback คือ bug — สำหรับแต่ละ failure เขียนว่าระบบ return อะไร
- failure ที่ออกแบบยากสุดคือ **out-of-corpus query** — LLM อยากตอบเสมอ ต้อง guard
