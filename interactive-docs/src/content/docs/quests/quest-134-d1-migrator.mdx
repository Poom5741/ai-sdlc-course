## 📖 Concept: Database Migrations

Database migration คือ "แผนที่เปลี่ยนแปลง schema" ของ database — มันบอกว่า table ต้องเพิ่ม column ไหน, เปลี่ยน type อะไร, หรือลบ table ไหน ที่สำคัญคือ migration ต้อง **reversible** — ต้องมีทั้ง "up" (ทำ) และ "down" (undo)

Cloudflare D1 ใช้ SQL migrations เหมือน SQLite database ทั่วไป ใน quest นี้คุณจะเรียนรู้ pattern ที่ generate migration SQL จาก parameters

**สิ่งสำคัญที่สุด:** เมื่อ DROP column — คุณ **ต้อง** preserve data ก่อนเสมอ Think ของมันเหมือน "move furniture ก่อนรื้อบ้าน" — ย้ายข้อมูลไป backup table ก่อน drop column

## ⚙️ How It Works

### Migration Generation Flow

```
1. รับ action, table, changes
         ↓
2. Validate inputs (table name, action type)
         ↓
3. Switch ตาม action type (create/alter/drop)
         ↓
4. Generate UP script (ทำ)
         ↓
5. Generate DOWN script (undo)
         ↓
6. Return { up, down, isValid, errors }
```

### Migration Actions

| Action | UP Script | DOWN Script |
| --- | --- | --- |
| `create` | `CREATE TABLE ...` | `DROP TABLE IF EXISTS ...` |
| `alter` (add) | `ALTER TABLE ADD COLUMN ...` | `ALTER TABLE DROP COLUMN ...` |
| `alter` (drop) | Backup → `ALTER TABLE DROP COLUMN` | Restore → `DROP TABLE backup` |
| `drop` | `DROP TABLE IF EXISTS ...` | Warning (data loss) |

### Data Preservation Pattern

```sql
-- UP: Preserve data before dropping columns
CREATE TABLE users_backup AS SELECT * FROM users;
ALTER TABLE users DROP COLUMN legacy_field;

-- DOWN: Restore dropped columns from backup
INSERT INTO users SELECT * FROM users_backup;
DROP TABLE users_backup;
```

## 💡 Example: Generating Migrations

**ขั้นตอนที่ 1: CREATE TABLE migration**

```javascript
const columns = [
  'id INTEGER PRIMARY KEY AUTOINCREMENT',
  'email TEXT UNIQUE NOT NULL',
  'name TEXT NOT NULL'
];

// UP
const up = `CREATE TABLE users (\n  ${columns.join(',\n  ')}\n);`;
// DOWN
const down = `DROP TABLE IF EXISTS users;`;
```

**ขั้นตอนที่ 2: ALTER TABLE ADD COLUMN**

```javascript
const addColumns = ['age INTEGER', 'phone TEXT'];

// UP
const up = `ALTER TABLE users\n  ADD COLUMN age INTEGER,\n  ADD COLUMN phone TEXT;`;
// DOWN
const down = `ALTER TABLE users\n  DROP COLUMN age,\n  DROP COLUMN phone;`;
```

**ขั้นตอนที่ 3: ALTER TABLE DROP COLUMN (with preservation)**

```javascript
// UP: Backup first, then drop
const up = `-- Preserve data before dropping columns
CREATE TABLE users_backup AS SELECT * FROM users;
ALTER TABLE users DROP COLUMN legacy_field;`;

// DOWN: Restore from backup
const down = `-- Restore dropped columns from backup
INSERT INTO users SELECT * FROM users_backup;
DROP TABLE users_backup;`;
```

## ⚠️ Common Mistakes

**Mistake 1: DROP column โดยไม่ backup data**
> "ลบ column ไปเลย ไม่ต้อง backup"
> → ข้อมูลจะหายตลอดกาล — เสมอ backup ก่อน DROP

**Mistake 2: DOWN script ไม่ reversible**
> UP script ทำได้แต่ DOWN script ไม่ undo ได้
> → Migration ที่ดีต้อง undo ได้เสมอ

**Mistake 3: ไม่ validate table name**
> table name ว่าง string ทำให้ SQL ผิด
> → Validate table name ก่อน generate SQL

**Mistake 4: DROP TABLE โดยไม่ check existence**
> `DROP TABLE users` ถ้า table ไม่มีจะ error
> → ใช้ `DROP TABLE IF EXISTS` เสมอ

## คำใบ้

- Actions ที่รองรับ: create, alter, drop
- DROP COLUMN ต้อง backup data ก่อนเสมอ (CREATE TABLE backup AS SELECT ...)
- ใช้ `DROP TABLE IF EXISTS` เสมอ
- DOWN script ต้อง undo ได้เสมอ
