## 📖 Concept: AI Code Completion

AI coding tools like GitHub Copilot, Cursor, and Claude Code can generate code from natural language comments. You describe what you want, and the AI writes the code for you.

This is incredibly powerful — but it comes with a critical caveat: **AI output is a starting point, not a finished product.** The AI generates code that looks correct for the obvious cases, but it often misses edge cases that a human developer would catch.

Think of AI code completion like a junior developer who writes code fast but doesn't think about edge cases. Your job is to be the senior developer who reviews, tests, and validates.

---

## ⚙️ How It Works

### The AI Code Completion Workflow

```
1. Write a comment describing what you want
         ↓
2. AI generates code suggestion
         ↓
3. Accept the suggestion
         ↓
4. Run tests — READ the failures carefully
         ↓
5. Fix edge cases the AI missed
         ↓
6. Verify all tests pass
```

### Why Verification Matters

Consider this AI suggestion for a factorial function:

```javascript
// Naive AI suggestion
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}
```

**This looks correct, right?** Let's check:

| Input | Expected | AI Output | Correct? |
| --- | --- | --- | --- |
| `factorial(5)` | 120 | 120 | ✅ |
| `factorial(1)` | 1 | 1 | ✅ |
| `factorial(0)` | 1 | 1 | ✅ |
| `factorial(-1)` | ❌ Error | 1 | ❌ **WRONG** |

The AI's `if (n <= 1) return 1` returns `1` for negative numbers, but factorial of a negative number is **undefined**. The function should throw an error.

**This is the #1 mistake developers make with AI:** accepting the first suggestion without testing edge cases.

---

## 💡 Example: The Right Way

Here's how an experienced developer handles AI code completion:

**Step 1: Write a descriptive comment**

```javascript
// Calculate factorial of n using recursion. 
// Throw error for negative numbers (undefined).
// Throw error for non-integers.
```

**Step 2: Review the AI suggestion critically**

```javascript
function factorial(n) {
  if (typeof n !== 'number' || !Number.isInteger(n)) {
    throw new Error('Input must be an integer');
  }
  if (n < 0) {
    throw new Error('Factorial is undefined for negative numbers');
  }
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}
```

**Step 3: Run the tests and READ the output**

```bash
node test.js
```

Don't just glance at "all tests pass" — read each test case to understand what it's checking.

**Step 4: If tests fail, understand WHY**

The failing test will tell you exactly what edge case you missed. This is valuable feedback, not a nuisance.

---

## ⚠️ Common Mistakes

**Mistake 1: Trusting AI blindly**
> "Copilot suggested it, so it must be correct"
> → Always run tests. Always check edge cases.

**Mistake 2: Not reading test failures**
> "Tests failed, let me just tweak until they pass"
> → Read the failure message. Understand what the test expects.

**Mistake 3: Copying from solution files**
> "I'll just peek at the solution to understand the pattern"
> → This defeats the learning. Struggle is where growth happens.

**Mistake 4: Ignoring error handling**
> "The happy path works, good enough"
> → Production code must handle edge cases. Negative inputs, null, undefined, wrong types.
