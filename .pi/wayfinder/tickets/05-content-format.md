# Ticket: Content Format Decision

## Question

How should skills content be presented for maximum effectiveness?

**Options:**
1. **Skill-as-Tool** - Each skill documented like a CLI tool (command, usage, examples)
2. **Skill-as-Workflow** - Each skill shown in context of a development workflow
3. **Skill-as-Story** - Narrative showing how skills transform "vibe coding" to "vibe engineering"
4. **Comparison Format** - Side-by-side: "Without skill" vs "With skill"

**Considerations:**
- Course positioning: "vibe coding" vs "vibe engineering" contrast
- Skills are invoked via slash commands (/grilling, /impeccable, etc.)
- learners need to know WHEN to use skills, not just HOW
- Visual hierarchy matters for reference docs

**Recommendation:** Option 3 (Skill-as-Story) for workshop block + Option 2 (Skill-as-Workflow) for reference docs. Workshop tells the transformation story; reference docs show practical usage in context.
