# Ticket: Coverage Depth Decision

## Question

How deep should the documentation go for each skill category?

**Options:**
1. **Overview Level** - What each skill does, when to use it, key concepts (1-2 pages per skill)
2. **Workflow Level** - Overview + step-by-step workflow examples (3-5 pages per skill)
3. **Command Reference** - Full command documentation with examples (5-10 pages per skill)
4. **Tiered Approach** - Overview in main content, detailed commands in reference section

**Skill Categories to Cover:**
- Matt Pocock Skills: grilling, domain-modeling, research, prototype, tdd, code-review, wayfinder, etc.
- Impeccable: critique, audit, polish, bolder, quieter, animate, etc.
- Ponytail: lite/full/ultra modes, YAGNI principles
- Pi Agent Skills: web-perf, cloudflare-*, agents-sdk, etc.

**Considerations:**
- Course targets both beginners and experienced developers
- Skills have steep learning curves
- Command syntax changes over time
- Workshop has limited time (90 min per block)

**Recommendation:** Option 4 (Tiered) - Workshop block covers concepts and when to use each skill category. Reference docs provide command-level detail. This balances depth with accessibility.
