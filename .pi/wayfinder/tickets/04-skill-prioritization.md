# Ticket: Skill Category Prioritization Decision

## Question

How should the **pipeline** be structured and presented?

**The Pipeline (Your Actual Workflow):**
```
Matt Skills (Planning) → GitHub Issues (Tracking) → Goal System (Execution)
```

**Layer 1: Planning (Matt's Skills)**
- Input: Loose idea, requirements, problems
- Tools: grilling, domain-modeling, wayfinder, research, prototype
- Output: GitHub issues with clear decision tickets

**Layer 2: Tracking (GitHub Issues)**
- Input: Decision tickets from planning
- Format: Issues with wayfinder labels, blocking relationships
- Output: Ordered queue of implementable work

**Layer 3: Execution (Goal System)**
- Input: GitHub issues from queue
- Tools: /goal, /list, /loop commands
- Execution skills: Impeccable, Ponytail, Pi Agent skills
- Output: Implemented, audited, verified work

**Considerations:**
- This is a SYSTEM, not just a list of skills
- The handoff between layers is key
- Each layer has its own skills and patterns
- The goal system automates what would otherwise be manual orchestration

**Recommendation:** Present as a 3-layer pipeline. Each layer gets its own section. Show how skills flow from planning → tracking → execution. This is the "vibe engineering" workflow that separates from "vibe coding."
